**Properties**

- necessary and sufficient conditions ( any 1 )
  - $max(L) < x < min(R)$ for all x, where $L$ and $R$ are subtrees
    - you can call it "partition" invariant of binary tree, each node PARTITIONS ranges, it'll be useful to think of this in lca context
  - inorder traversal is increasing
  - every node satisfies it's ancestor defined bounts ( look up and get the bounds )
  - Solve [Validate BST](https://leetcode.com/problems/validate-binary-search-tree/description/) via each
- in a height balanced BST, root will be the median of subtree elems
  - [Convert sorted array to BST](https://leetcode.com/problems/convert-sorted-array-to-binary-search-tree/)
  - [same as above but with linked list](https://leetcode.com/problems/convert-sorted-list-to-binary-search-tree/description/)
    - don't materialise the linked list to an array of course
- flatten it via inorder works for a LOT many problems that ask for the smaller or greater to a current node

The following problems are derived from properties as well but are a little bit more focused on the implemenational patterns related to all this

**inorder traversal**

- ( trivial ) [kth smallest element in bst](https://leetcode.com/problems/kth-smallest-element-in-a-bst/description/)
- without flattening, find inorder successor and predecessor
  - from root
  - if you are at the node ( assume you can go to parent )
- [recover bst](https://leetcode.com/problems/recover-binary-search-tree/)
  - note that there can be 1 OR 2 **adjancent** inversions by the swap
  - just keep track of inversions and needed state, let a second one overwrite the first
- [iterator](https://leetcode.com/problems/binary-search-tree-iterator/)
  - replicate the recursion with a stack, a little bit non-trivial to implement
    - some problems that _use_ the idea of this iterator
    - [two sum in bst](https://leetcode.com/problems/two-sum-iv-input-is-a-bst/description/)
    - [merge two BSTs to list](https://leetcode.com/problems/all-elements-in-two-binary-search-trees/submissions/2127544036/)
- [clostest nodes](https://leetcode.com/problems/closest-nodes-queries-in-a-binary-search-tree/)
  - problem is asking to the previous and next element in ordered traversal
- [add all nodes more than cur](https://leetcode.com/problems/binary-search-tree-to-greater-sum-tree/description/)
  - similar idea as above, if you flatten it to inorder, it's really trivial
